# Крошка

Небольшой многостраничный сайт кофейни-пекарни на обычных HTML, CSS и JavaScript. Фреймворки, сервер и платёжные интеграции не используются.

## Страницы

- `index.html` — главная;
- `menu.html` — каталог, поиск, категории, сортировка и корзина;
- `about.html` — о кофейне;
- `visit.html` — адрес, часы работы и ссылка на Google Maps;
- `order.html` — оформление самовывоза.

Каталог находится в `menu-data.js`. Общая логика корзины, темы и навигации — в `js_main1.js`; сценарий заказа — в `order.js`.

## Запуск

Для быстрой проверки можно открыть `index.html` в браузере. Для локального веб-сервера подойдёт любой статический сервер; сборка не требуется. GitHub Pages публикует сайт из корня репозитория.

## Корзина и оформление

Корзина, тема и последний заказ хранятся локально в браузере посетителя. Заказ предусматривает самовывоз по адресу Москва, ул. Пекарская, 12. До настройки внешнего сервиса оформление работает в демо-режиме: показывает номер и итог заказа, сохраняет локальную историю и позволяет скопировать текст заказа. Данные владельцу сайта в этом режиме не отправляются.

## Подключение реальной отправки

1. Создайте endpoint у сервиса, который принимает POST-запросы с JSON из браузера и разрешает CORS для домена сайта.
2. В `order-config.js` присвойте `window.KROSHKA_ORDER_ENDPOINT` URL этого endpoint вместо пустой строки.
3. Отправьте тестовый заказ и убедитесь, что сервис принял его. Успешный HTTP-ответ сервиса переводит форму в подтверждение реального оформления; при ошибке корзина остаётся сохранённой.

Не помещайте в `order-config.js` API-ключи, пароли или Telegram Bot Token: этот файл публично доступен всем посетителям сайта. Если сервис требует секретный ключ, отправку нужно выполнять через защищённый серверный/serverless endpoint, который хранит секрет на своей стороне.

Отправка в Telegram отдельно не настроена. Для неё потребуется такой защищённый endpoint; токен бота нельзя публиковать в браузерном JavaScript.
